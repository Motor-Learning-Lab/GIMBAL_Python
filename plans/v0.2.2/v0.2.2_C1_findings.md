## Current Status (Updated 2026-08-11)

The ladder infrastructure (`scripts/run_ladder.py`, stages A–J, `datasets/ladder/L00-L07.yaml`)
runs end-to-end mechanically. **No rung has ever produced a converged fit.** The easiest
rung (L00) fails the same Stage H convergence gate the ladder itself defines. This means
the ladder currently has no valid Level 0 — see Issue #8.

Separately, the December 2025 divergence investigation (I1/I2/I3, summarized below)
already identified two levers that *do* produce convergence on a comparably-sized
synthetic problem, when applied as a constraint on the **model**, not the data:
constraining parameter redundancy (I3) works; anchoring the root alone (I1) does not;
replacing the camera likelihood (I2's diagnostic ablation) helps but does not fully fix
it. See "Carried-forward findings" below.

**Working hypothesis for a real Level 0:** the TG11b configuration (strong data-driven
priors) plus an additional constraint on `eta2_root`, which was TG11a's one remaining
failing parameter. Not yet tested — this is the next experiment (see "Open questions").

## Carried-forward findings (I1 / I2 / I3)

These issue IDs are defined in `plans/v0.2.1/v0.2.1_divergence_plan_2.md` and are not
redefined here — only summarized, with a link back to the source. Do not restate their
detail elsewhere; link to this table or the source document instead.

All four experiments below: T=100, 6 joints, 3 states, 3 cameras, 500 draws / 500 tune /
2 chains, seed 42. Gate used throughout this document: 0 divergences, max R-hat ≤ 1.05,
min ESS ≥ 100 (this repo's Stage H criteria).

| ID | Test | Variant | Divergences | Max R-hat | Min ESS | Gate? |
|---|---|---|---|---|---|---|
| I1 | TG09 (2025-12-13) | baseline (Gamma priors, non-centered root) | 1000/1000 | 14,462,920 | 2.0 | ✗ |
| I1 | TG09 | root fixed (DLT, no dynamics) | 1 | 1.897 | 31.0 | ✗ |
| I2 | TG10 (2025-12-14) | baseline (camera-projection likelihood) | 1000/1000 | 14,462,920 | 2.0 | ✗ |
| I2 | TG10 | direct-3D likelihood (diagnostic ablation, not a shippable fix) | 32/1000 | 2.901 | 3.8 | ✗ |
| I3 | TG11a (2025-12-14) | baseline (free directions/lengths) | 1000/1000 | 14,462,920 | 2.0 | ✗ |
| I3 | TG11a | fixed to ground truth (degenerate — not usable in production) | 0 | **1.054** | 35.5 | ✗ (barely — one parameter, `eta2_root`) |
| I3 | TG11b (2025-12-14) | strong data-driven priors (length SD 2%, direction SD 0.05) | 0 | 1.337 | 5.0 | ✗ |

Source data: `tests/diagnostics/v0_2_1_divergence/results_tg{09,10,11a,11b}_*.json`,
reports in the same directory.

**Conclusions carried forward (from the source document, 2025-12-14):**
- I2 (camera projection conditioning) is the primary cause of divergence.
- I3 (parameter redundancy between root motion, directions, and bone lengths) is a
  co-equal critical bottleneck, not masked by I2.
- Both hard-fixing (TG11a) and strong informative priors (TG11b) eliminate divergences
  entirely. Root-anchoring alone (I1) does not.
- **Both I2 and I3 must be addressed for a working sampler** — this is why A1 (camera
  priors) and A2 (segment-length priors) are both scoped in `v0.2.2_overview.md`.
- TG11a's *only* failing parameter, in an otherwise-passing run, was `eta2_root` (root
  random-walk variance) — R-hat 1.054, ESS 35.5. Every other parameter passed cleanly
  (ESS 617–1566, R-hat ~1.02).

## New measurement: L00 on the current C1 ladder (2026-08-11)

Ran `pixi run python scripts/run_ladder.py L00_minimal --stages A-J` on the
`c1-capability-ladder` branch (post module-reorg, post `gp`-alias bugfixes). L00 is
smaller than the TG-series problems above (4 joints, 1 state, 3 cameras, T=200) and uses
the current production model, not a diagnostic ablation.

Stages A–G pass. Stage H:

| Draws | Tune | Chains | Divergences | Max R-hat | Min ESS |
|---|---|---|---|---|---|
| 200 | 500 | 2 | 2 | 3.059 | 2.0 |

Step size collapsed toward 0 during tuning. 16,843/16,843 parameters failed the R-hat
threshold.

For comparison, the last recorded fit on this same L00 dataset before the reorg
(`tests/pipeline/fits/v0.2.1_L00_minimal/sampling_metrics.json`, 2025-12-20) was far
worse: 400/400 divergences, max R-hat 26,835,526, min ESS 2.08. Today's run is not
passing, but it is a different order of severity — worth noting rather than ignoring,
since it means *something* about the current setup (data-driven priors already partly
enabled per the Stage G output) is better than the December baseline, just not enough.

**Conclusion: L00, the ladder's intended easiest rung, does not converge.** Per its own
YAML header ("Any failing here is a model/toolchain bug"), this is a bug by the ladder's
own definition — not evidence the model needs a harder or easier dataset. It is not yet
known which lever (I2-class fix, I3-class fix, or a smaller L00) would fix it, because
no I2/I3 fix has been tried against L00's actual configuration.

## Open questions / next steps

1. **Untested combination:** TG11b's prior configuration (length SD 2%, direction SD
   0.05) plus a constraint on `eta2_root` (TG11a's one residual failure). If this passes
   the gate on a TG-comparable problem, it is a strong candidate for Level 0 — see
   Issue #8.
2. Whether L00's specific configuration (4 joints, 1 state — smaller than any TG test)
   converges once an I3-class constraint is applied, or whether the camera-projection
   likelihood (I2) is independently required even at this size.
3. A1/A2 (Issues #3, #4) are the production-code path for delivering the I2/I3 fixes
   that TG10/TG11b demonstrated as diagnostic ablations; they are not yet implemented.
