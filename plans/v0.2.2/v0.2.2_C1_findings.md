## Current Status (Updated 2026-08-12)

The ladder infrastructure (`scripts/run_ladder.py`, stages A–J, `datasets/ladder/L00-L07.yaml`)
runs end-to-end mechanically. **No rung has ever produced a converged fit.** The easiest
rung (L00) fails the same Stage H convergence gate the ladder itself defines. This means
the ladder currently has no valid Level 0 — see Issue #8.

Separately, the December 2025 divergence investigation (I1/I2/I3, summarized below)
already identified two levers that *do* produce convergence on a comparably-sized
synthetic problem, when applied as a constraint on the **model**, not the data:
constraining parameter redundancy (I3) works; anchoring the root alone (I1) does not;
replacing the camera likelihood (I2's diagnostic ablation) helps but does not fully fix
it. See "Carried-forward findings" below.

**Working hypothesis for a real Level 0 (revised 2026-08-12, see TG13/TG14 below) —
SUPERSEDED, see "Correction: TG10–TG13's root random walk has a coordinate/time axis
bug" below:** TG13 (non-centered `length_k` vs. `sigma2_k`, on top of TG11b's strong
priors) is the closest result yet to a full pass: 0 divergences, max R-hat 1.0415
(passes), min ESS 39.0 (fails, want ≥100), on a TG-comparable problem, without fixing
anything to ground truth. TG14 (also non-centering the root walk) made things worse and
was rejected. Next: more sampling on TG13's exact configuration, not more
reparameterization.

**Corrected working hypothesis (2026-08-12):** TG13's pass has no evidential value — its
root random walk is built with the wrong shape argument and carries no temporal prior at
all (see correction section below). TG14, previously rejected, has the only correctly
specified root walk in the TG10–TG14 series and recovers ground truth closely (root
position error 1.21 world units vs. TG13's 107.3). There is currently no result
establishing a working Level 0; see "Open questions / next steps" (items 7–11) for the
revised plan.

**Current working hypothesis (2026-08-15):** both TG13 (axis-corrected) and TG14 now
cleanly pass all three Stage H gates in the diagnostic harness, once the DLT `eta2_root`
initializer-bias fix ([Issue #11](https://github.com/Motor-Learning-Lab/GIMBAL_Python/issues/11),
merged to `main` via PR #12) is included — see "TG13/TG14 rerun with corrected axis and
DLT init fix" below. Production code (`gimbal_pymc/hmm/observation_model.py`) already
has the axis-correct root walk, the depth-singularity fix, and the DLT fix from PR #12;
it does not yet have TG13's non-centered `length_k`/`sigma2_k` reparameterization. That
gap — and whether closing it makes `L00_minimal`'s actual dataset (not the TG harness's
generic synthetic setup) pass Stage H for the first time — is untested. See "Plan: port
TG13's fix to production" below; **not yet attempted as of this writing.**

reports in the same directory.

**Conclusions carried forward (from the source document, 2025-12-14):**
- I2 (camera projection conditioning) is the primary cause of divergence.
- I3 (parameter redundancy between root motion, directions, and bone lengths) is a
  co-equal critical bottleneck, not masked by I2.
- Both hard-fixing (TG11a) and strong informative priors (TG11b) eliminate divergences
  entirely. Root-anchoring alone (I1) does not.
- **Both I2 and I3 must be addressed for a working sampler** — this is why A1 (camera
  priors) and A2 (segment-length priors) are both scoped in `v0.2.2_overview.md`.
- TG11a's *only* failing parameter, in an otherwise-passing run, was `eta2_root` (root
  random-walk variance) — R-hat 1.054, ESS 35.5. Every other parameter passed cleanly
  (ESS 617–1566, R-hat ~1.02).

**Caveat added 2026-08-12:** TG10's ablation variant, TG11a's fixed-to-ground-truth
variant, and TG11b's strong-priors variant all build their root random walk with the
same shape bug described in "Correction: TG10–TG13's root random walk has a
coordinate/time axis bug" below (the shared 1000/1000-divergence baselines above them,
which use the production model builder, do not). This does not overturn the I2/I3
conclusions above, but it means they were drawn from runs where the root had no temporal
prior and could collapse freely to minimize the camera-likelihood cost — they have not
been re-verified against a correctly specified root walk.

## TG12: root-variance constraint on top of TG11b (2026-08-11)

Tested the hypothesis from "Open questions" #1 below: TG11b's strong priors
(length SD 2%, direction SD 0.05) plus a tighter prior on `eta2_root`, sweeping
`eta2_root_sigma` ∈ {0.5, 0.1, 0.02} against TG11b's own baseline (`sigma=0.5`, which
scored max R-hat 1.337 / min ESS 5.0 at full length).

**Pilot** (100 draws/200 tune/2 chains, fast but not a reliable R-hat/ESS read):
0 divergences held at all three values, but R-hat got *worse* as sigma tightened
(1.89 → 2.08 → 2.57), with the worst parameter shifting between runs.

**Full confirmation** (500 draws/500 tune/2 chains, matching TG11b's own rigor, at
`eta2_root_sigma=0.02`, the tightest value): **3 divergences, max R-hat 2.448, min ESS
2.5** — worse than TG11b's baseline on every metric.

**Result: hypothesis refuted.** Constraining `eta2_root` does not fix the residual
failure; it makes convergence worse. `eta2_root` itself was never the worst-R-hat
parameter in any of the four runs.

**New pattern, found by looking at what *was* consistently worst:** the bone-length
variance parameters (`sigma2_k`) were the single worst-R-hat parameter in 3 of 4 runs,
and a top-2 offender in the fourth. `sigma2_k` already has a tight `HalfNormal(0.01 *
length_gt)` prior in TG11b's code — tightness isn't the issue. The model wraps it in a
classic funnel shape: `sigma2_k` (near zero, weakly identified) controls the scale of
`length_k[t] ~ Normal(rho_k, sqrt(sigma2_k))` for all T timepoints, directly
(centered parameterization) — structurally the same pathology non-centered
reparameterization exists to fix (Neal's funnel). Not yet tested.

Source: `tests/diagnostics/v0_2_1_divergence/test_tg12_i1i3_root_variance_constrained.py`,
`results_tg12_i1i3_root_variance_constrained.json`.

## TG13: non-centered length_k vs sigma2_k (2026-08-11)

Tested the funnel hypothesis from TG12: replaced `length_k[t] ~ Normal(rho_k,
sqrt(sigma2_k))` (centered) with a non-centered transform (`length_k_raw ~ Normal(0,1)`,
`length_k = rho_k + length_k_raw * sqrt(sigma2_k)`), everything else identical to
TG11b/TG12 (`eta2_root_sigma=0.5`, the untightened baseline value).

**Pilot:** 0 divergences, max R-hat 1.56, min ESS 22.4 — vs. the centered model's own
pilot at the same `eta2_root_sigma` (TG12: max R-hat 1.89, min ESS 3.0). `sigma2_k` no
longer the worst parameter anywhere.

**Full (500/500/2): 0 divergences, max R-hat 1.0415, min ESS 39.0.** R-hat and
divergence gates **pass**. Only ESS (want ≥100) fails, and by less than 3x. The single
remaining worst parameter is `eta2_root` — R-hat 1.042, ESS 39.0, almost exactly
TG11a's own residual failure (R-hat 1.054, ESS 35.5) — reached here **without fixing
anything to ground truth**, unlike TG11a.

**Result: hypothesis confirmed.** The `sigma2_k`/`length_k` funnel was real and fixable.
This is the best result in this entire investigation, TG09 through TG14 — 2 of 3 gate
criteria passing at full sampling length.

Source: `tests/diagnostics/v0_2_1_divergence/test_tg13_i3_noncentered_length.py`,
`results_tg13_i3_noncentered_length.json`.

## TG14: non-centered root random walk on top of TG13 (2026-08-11) — refuted

Since TG13 left `eta2_root`/`x_root` as the sole bottleneck, and `x_root ~
GaussianRandomWalk(sigma=sqrt(eta2_root))` has the identical centered-funnel shape,
applied the same non-centering fix to it (manual `x_root0` + cumulative sum of raw
unit-normal steps scaled by `sqrt(eta2_root)`), on top of TG13's already-fixed
`length_k`.

**Pilot: 6 divergences, max R-hat 2.31, min ESS 2.7** — worse than TG13 on every
metric, and the worst parameter moved away from `eta2_root` entirely (`length_1_raw` /
`obs_sigma`), meaning this change destabilized parts of the model that TG13 had
already fixed. Divergence counts are reliable even at pilot length (they don't depend
on ESS), so this is a real regression, not noise — **no full run needed to reject it.**

**Result: hypothesis refuted, this specific approach.** Root cause not yet
investigated — candidates: the manual non-centered construction differs from
`pm.GaussianRandomWalk`'s own implementation in some way that hurts geometry, or the
wide `x_root0 ~ Normal(0, 100)` initial-point prior (carried over from
`GaussianRandomWalk`'s default `init_dist`, never itself examined) is poorly scaled
against the now non-centered increments. Not investigated further — TG13 alone is
close enough to the gate that the next cheap step (more sampling, not more
reparameterization) should be tried first.

Source: `tests/diagnostics/v0_2_1_divergence/test_tg14_i1_noncentered_root.py`,
`results_tg14_i1_noncentered_root.json`.

## Correction: TG10–TG13's root random walk has a coordinate/time axis bug (2026-08-12)

Requested as an identifiability investigation into why `eta2_root` is hard to pin down
(motivated by TG13's near-pass above); found instead that TG13's pass is an artifact of
a shape bug in the test harness, not evidence of a working model.

**Mechanism.** `test_tg13_i3_noncentered_length.py:81` — and `test_tg10_i2_direct_3d.py:110`,
`test_tg11a_i3_redundancy_fixed.py:151`, `test_tg11b_i3_redundancy_priors.py:151`, and
`tests/unit/test_pymc_utils.py:55` (which `TG12` inherits via TG11b's model builder) —
construct the root walk as:

```python
x_root = pm.GaussianRandomWalk("x_root", mu=0.0, sigma=pt.sqrt(eta2_root), shape=(T, 3), ...)
```

In the installed PyMC (5.26.1), a `GaussianRandomWalk`'s steps run along the *last* axis
of `shape`. With `shape=(100, 3)` this builds **100 independent 3-step walks across
x→y→z within each frame**, not a walk across 100 frames. Verified directly (isolated
5-frame model, `eta2=1`): perturbing the coordinate axis costs 125.0 nats of log-prior;
perturbing the time axis costs 0.005 nats. **The root carries no temporal smoothness
prior in these five files.** Production code, `gimbal_pymc/hmm/observation_model.py:517-533`,
builds the walk correctly (explicit `cumsum(axis=0)`) and is unaffected, as is TG14
(`test_tg14_i1_noncentered_root.py`, manual `x_root0 + cumsum(steps, axis=0)`).

**What the bug lets the sampler do.** With no temporal constraint, the cheapest way to
satisfy the (misapplied) coordinate-axis prior is to collapse the skeleton toward a
point and pay for the camera-likelihood mismatch by inflating `obs_sigma` instead.
Posterior summaries from the saved traces (`trace_tg13_i3_noncentered_length.nc`,
`trace_tg14_i1_noncentered_root.nc` — both pilot-length, 2 chains × 100 draws; see the
artifact/doc mismatch note below):

| quantity | TG13 (coordinate-axis bug) | TG14 (correct time axis) | Truth |
|---|---|---|---|
| `eta2_root` | 1.757 ± 0.527 | 0.716 ± 0.124 | ~1.0 |
| `obs_sigma` | 6.98 ± 0.09 | 0.4975 ± 0.0062 | 0.5 |
| root position error, posterior mean vs. truth | **107.3** (max 157.2) | **1.21** (max 2.49) | — |
| all-joint position error | 106.2 | 1.19 | — |
| corr(`eta2_root`, within-frame coordinate-step²) | **+0.955** | — | — |
| corr(`eta2_root`, across-frame temporal-step²) | −0.206 | **+0.884** | — |
| `eta2_root` R-hat / ESS (this trace) | 1.17 / 9.5 | 1.009 / 70.5 | — |

The 0.955 correlation between `eta2_root` and the within-frame coordinate-step² is the
fingerprint of which axis the walk actually ran on. The prior-vs-likelihood accounting
confirms the trade is real: the coordinate-walk log-prior at the true root path is
−267,150 nats; at TG13's collapsed posterior mean it is −806 nats; the resulting
+266,344 nat gain outweighs the −9,300 nat cost of inflating `obs_sigma` by roughly 29×.
TG14's correctly specified walk instead has to fit the actual data — its somewhat harder
sampling geometry, next to a fit that recovers ground truth almost exactly, is the
expected signature of a model that cannot take this shortcut.

**Why TG14 was read as "worse."** TG13 and TG14 are not centered-vs-non-centered
variants of the same model — they are different models (coordinate-axis walk vs.
time-axis walk). The TG14 section above compares a prior-dominated posterior (TG13)
against a data-dominated one (TG14) and attributes the latter's harder sampling geometry
to the reparameterization; it is better explained as the expected cost of fitting real
correlated structure instead of exploiting the axis bug.

**Artifact/doc mismatch, independent of the bug above:** the diagnostics quoted in the
TG13 and TG14 sections above do not match the `results_*.json` files currently on disk,
both last written 2026-08-12 00:57 — later than the numbers recorded in this document.
TG13's on-disk file reports pilot max R-hat 1.70 / min ESS 9.5 (this document says
1.56 / 22.4); TG14's on-disk file reports **0 divergences, max R-hat 1.126, min ESS
70.5** (this document says 6 divergences, max R-hat 2.31, min ESS 2.7). On the current
on-disk artifacts, TG14 beats TG13 on every sampling diagnostic, in addition to having
the only correctly specified root walk. This needs reconciling on its own, separately
from the axis-bug fix (see item 9 below).

**Also found, unrelated to the above:** `extract_ground_truth.py` indexes
`skeleton.bone_lengths[k-1]` where the generator uses `[k]` — an off-by-one on the
`length_k` ground-truth value it reports. Does not affect TG13/TG14 themselves, which
index `lengths_true[k+1]` and are consistent with the generator.

Source: direct inspection of `test_tg13_i3_noncentered_length.py`,
`test_tg14_i1_noncentered_root.py`, and `gimbal_pymc/hmm/observation_model.py`; posterior
analysis of the saved `trace_tg13_i3_noncentered_length.nc` and
`trace_tg14_i1_noncentered_root.nc` traces (ArviZ).

## Plan: port TG13's fix to production, validate `L00_minimal` (2026-08-15) — planned, not yet executed

**What:** the TG13/TG14 rerun above used the diagnostic harness's own generic synthetic
setup (`test_utils.get_standard_synth_data`, T=100, C=3, S=3), not `L00_minimal.yaml`'s
actual dataset (T=200, 4-joint skeleton, specific camera geometry, 2px noise). Production
code (`build_camera_observation_model` in `gimbal_pymc/hmm/observation_model.py`) already
has the axis-correct root walk and the merged depth/DLT fixes (PR #12), but still builds
`length_k` with the **centered** parameterization
(`pm.Normal(mu=rho[k], sigma=sqrt(sigma2[k]))`) rather than TG13's non-centered form. This
is the one identified gap between "diagnostic proof of concept" and "the actual production
pipeline `stage_h_fitting.py` calls."

**Planned change:** port TG13's non-centered `length_k`/`sigma2_k` reparameterization
(`length_k_raw ~ Normal(0,1)`, `length_k = rho_k + length_k_raw * sqrt(sigma2_k)`) into
`build_camera_observation_model`. TG14's additional root-walk non-centering is *not*
planned for porting, per the TG13-alone result above — worth testing without it first.

**Validation plan:** run `L00_minimal` through the real pipeline
(`pixi run ladder-run L00_minimal`, i.e. `stage_h_fitting.run_stage_h`, not the TG
harness) and check its own Stage H gate (`criteria_Q7`: `rhat_pass` at R-hat<1.05,
`divergence_pass` at 0 divergences, `ess_pass` at ESS>100 — same thresholds as the TG
tests). This is a real, unproven test, not a formality: `L00_minimal`'s dataset differs
from the TG harness's in size (T=200 vs. 100), skeleton (4 joints vs. the TG default),
and camera geometry, and per Issue #6's own history the ladder infrastructure has never
produced a converged fit on any rung, including this one, before now.

**Success criterion:** `L00_minimal` passes all three Stage H gates for the first time.
**Failure handling:** if it doesn't pass, report what the results show (which gate fails,
by how much, which parameter) here — per this document's own convention — rather than
retrying silently or asserting partial success.
