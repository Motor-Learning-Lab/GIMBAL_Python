## Goal

Restructure the flat `gimbal_pymc/` package (17 modules, ~6,400 lines) into 6 domain-specific subpackages with clearer naming, remove deprecated torch_legacy code, and consolidate duplicate utilities.

**Key Principles:**
- Rename files for clarity during move (document mapping in completion report)
- Use explicit imports from subpackages (`from gimbal_pymc.hmm.engine import ...`)
- NO convenience exports - all imports must use full subpackage paths
- **No backward compatibility** - no aliases, no shims, no legacy module paths
- All internal repo callsites updated to canonical import paths
- Batch all moves, then fix all imports together

"""GIMBAL: Geometric Manifolds for Body Articulation and Localization.

[Keep existing docstring header...]

v0.2.2 Module Organization
===========================

The package is organized into focused subpackages:

**hmm/** - Hidden Markov Model components
    - engine: Collapsed HMM forward algorithm (Stage 1)
    - directional_prior: Directional HMM prior (Stage 3)
    - observation_model: Camera observation model builder (Stage 2)
    - gaussian_example: Example Gaussian HMM implementation

**cameras/** - Camera projection and triangulation
    - projection: Camera projection utilities
    - triangulation: DLT and Anipose triangulation
    - identifiability: Camera configuration validation

**skeleton/** - Skeletal structure and motion
    - config: Skeleton configuration and validation
    - synthetic_data: Synthetic data generation
    - metrics: Quality metrics for skeletal motion
    - visualization: Visualization utilities

**joints/** - Joint-level operations
    - distributions: VonMisesFisher and other joint distributions
    - statistics: Direction distribution analysis

**priors/** - Prior specification and initialization
    - building: Prior distribution builders
    - initialization: Parameter initialization strategies
    - utils: Nutpie integration utilities

**data_cleaning/** - Data preprocessing (v0.2.1)
    - cleaning: 2D/3D keypoint cleaning

Quick Start
-----------
>>> import pymc as pm
>>> from gimbal_pymc.skeleton.synthetic_data import generate_demo_sequence
>>> from gimbal_pymc.skeleton.config import DEMO_V0_1_SKELETON
>>> from gimbal_pymc.priors.initialization import initialize_from_observations_dlt
>>> from gimbal_pymc.hmm.observation_model import build_camera_observation_model
>>> from gimbal_pymc.hmm.directional_prior import add_directional_hmm_prior
>>>
>>> # Generate synthetic data
>>> data = generate_demo_sequence(DEMO_V0_1_SKELETON)
>>>
>>> # Initialize from observations
>>> init_result = initialize_from_observations_dlt(
>>>     y_observed=data.y_observed,
>>>     camera_proj=data.camera_proj,
>>>     parents=DEMO_V0_1_SKELETON.parents,
>>> )
>>>
>>> # Build model
>>> with pm.Model() as model:
>>>     build_camera_observation_model(
>>>         y_observed=data.y_observed,
>>>         camera_proj=data.camera_proj,
>>>         parents=DEMO_V0_1_SKELETON.parents,
>>>         init_result=init_result,
>>>     )
>>>     U = model["U"]
>>>     log_obs_t = model["log_obs_t"]
>>>     add_directional_hmm_prior(U, log_obs_t, S=3)
"""

# Subpackage imports - use explicit subpackage paths for all imports
from . import hmm

from . import joints
from . import priors
from . import data_cleaning

__all__ = [
    "hmm",
    "cameras",
    "skeleton",
    "joints",
    "priors",
    "data_cleaning",
]

2. **Torch legacy removal:** Removed more functions than originally specified:
   - `estimate_temporal_variances()`
   - `estimate_skeletal_parameters()`
   - `estimate_root_dynamics()`
   - `estimate_outlier_parameters()`
   - `estimate_pose_priors()`
   - `build_gimbal_parameters()`
   - Plus all torch imports and Tensor type hints

3. **Approach:** Used batch processing (all file moves, then all import updates) as planned, which worked efficiently.

4. **Subagent usage:** Delegated complex refactoring tasks (Phase 4-5) to a subagent for efficiency, which completed successfully.
