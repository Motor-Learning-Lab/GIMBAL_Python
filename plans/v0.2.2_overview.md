# GIMBAL v0.2.2 Overview

**Purpose:** This document specifies the v0.2.2 concrete, parallelizable subprojects with clear interfaces (“contracts”), deliverables, and success criteria. It is written for a small programming team working collaboratively in a single lab GitHub repo.

**Guiding principles for v0.2.2**

* **Use existing data before adding complexity.** Prioritize Anipose-derived camera/3D information and subject metadata.
* **Stabilization and reproducibility over feature growth.** The core architecture from v0.2.1 stands; v0.2.2 is about creating a ladder of datasets of increasing complexity to challenge the sampling algorithm and a number of approaches we think will make the sampling more stable.
* **Explicit contracts between modules.** Prevent merge conflicts and rework by defining file schemas and APIs up front.
* **Diagnostics are the arbiter.** Every major change should show measurable improvement on the capability ladder.

## P0. Anipose Processing & Prior-Inputs Pipeline (Prerequisite)

### Goal

Turn Anipose outputs into standardized “prior input products” that feed A1/A2/A3 and diagnostics.

### Inputs

* `calibration.toml` (Anipose)
* triangulated 3D keypoints (per frame/joint), plus confidence if available
* optionally per-camera 2D detections and/or reprojection residuals
* subject metadata (species/strain, sex, age, weight/height)
* skeleton definition (joint names + parents)

### Outputs (canonical directory layout)

For subject/session `SID`:

* `data/derived/SID/anipose_priors/camera_means.json`
* `data/derived/SID/anipose_priors/camera_scales.json`
* `data/derived/SID/anipose_priors/camera_quality.json`
* `data/derived/SID/anipose_priors/segment_length_means.json`
* `data/derived/SID/anipose_priors/segment_length_sds.json`
* `data/derived/SID/anipose_priors/segment_length_quality.json`
* `data/derived/SID/anipose_priors/coverage.json`
* (optional) `data/derived/SID/anipose_priors/anchors_3d.npz` (x[t,k,3], mask, sigma)

### Contracts (schemas)

* Define JSON schemas with explicit units and parameterization.
* Define a joint-name mapping layer: Anipose names → GIMBAL indices.

### Implementation (proposed modules)

* `gimbal/anipose_io/ingest.py` (file reading + normalization)
* `gimbal/anipose_io/stats.py` (length stats, coverage, quality metrics)
* `gimbal/anipose_io/schemas.py` (pydantic/dataclass schemas)
* `scripts/build_anipose_priors.py` (CLI entrypoint)

### Success criteria

* Deterministic pipeline output for a fixed input + config.
* Produces valid schema outputs and coverage summary.
* Provides segment length estimates within expected scale.

### Deliverables

* CLI script + docs: how to run it
* One example subject checked into a small test fixture or synthetic equivalent

## A2. Camera Priors from Anipose Calibration (High Priority)

### Goal

Use Anipose calibration to provide **informative camera priors** (not fixed constants) to reduce pathological posterior geometry.

### Dependencies

* P0 camera_means/scales/quality

### Scope

* Parameterize camera extrinsics robustly (axis-angle or quaternion + translation).
* Intrinsics: focal length, principal point, distortion (as supported by current model).
* Prior widths derived from:

  * calibration residuals (preferred), or
  * conservative defaults if residuals unavailable.

### Implementation

* `gimbal/priors/cameras.py`

  * `build_camera_priors(anipose_camera_bundle, model_paramization) -> priors`
* Integrate into `build_camera_observation_model(...)` via flags:

  * `use_camera_priors: bool`
  * `camera_prior_source: {"anipose", "user", "fixed"}`

### Tests

* Unit tests: parameter transformations are consistent.
* Integration test: build model with priors and confirm finite logp/grad.

### Success criteria

* Reduces divergences on a selected diagnostic rung compared to baseline.

## A1. Segment Length Priors (Anipose + Population Models) (High Priority)

### Goal

Replace weak length priors with **data-informed** and **biologically plausible** priors to reduce redundancy among root/directions/lengths.

### Dependencies

* P0 segment_length_means/sds + subject metadata

### Scope

1. **Anipose-derived segment priors**

* Use segment length distributions computed from triangulated 3D.
* Make uncertainty depend on coverage/quality (coverage-conditioned SD).

2. **Population priors using subject characteristics**

* Create a simple mapping from subject metadata to expected segment lengths.
* Allow blending:

  * `rho_prior = w * anipose + (1-w) * population`
* Provide a configuration mechanism for users to supply measurements.

3. **Revisit time-varying per-frame length model**

* Keep “soft tissue / landmark jitter” flexibility but constrain it.
* Decide default CV for `rho` and `sigma2` (move away from 100% CV).

### Implementation

* `gimbal/priors/segment_lengths.py`

  * `build_segment_length_priors(stats, population_model, config)`
* `gimbal/priors/population.py`

  * population mean/variance functions (pluggable)

### Tests

* Unit tests on prior parameter conversion
* Integration: verify reduced divergences in diagnostics

### Success criteria

* Demonstrable divergence reduction without fixing lengths.
* Reasonable posterior length estimates on synthetic and/or Anipose-initialized data.

## A3. General Joint Anchoring (Root + Arbitrary Joints)

### Goal

Support optional anchoring of one or more joints to external high-quality 3D data (Anipose or user-provided), with explicit uncertainty.

### Dependencies

* Optional: P0 anchors_3d output

### Scope

* Allow specifying an anchor set: `{joint_indices}` or joint names.
* Anchors can be:

  * per-frame time series (x[t,k,3])
  * fixed points
* Each anchor has sigma (global per joint, or per frame).

### Implementation

* `gimbal/priors/anchors.py`

  * `add_anchor_potential(model, x_all, anchors, sigma, mask)`
* Integration into model builder via `anchor_config`.

### Tests

* Confirm anchoring can eliminate the “root drives divergences” mode.

### Success criteria

* Root anchoring reduces divergences on baseline camera model.
* Anchoring other joints works without breaking shapes/gradients.

## C1. Capability Ladder Benchmarks (Important)

### Goal

Create a shared, reproducible benchmark ladder to track “how far we can go” under combined complexity.

### Scope

* Define **8 combined steps** increasing complexity across:

  * # joints, topology, camera coverage, noise/occlusions/outliers, sequence length
* Separate “very long T” scaling into a distinct temporal ladder.

### Implementation

* `benchmarks/ladder/step01.yaml` … `step08.yaml`
* `benchmarks/run_ladder.py`

  * runs specified step + inference method
  * outputs standardized results JSON + brief markdown summary
* Output directory:

  * `diagnosis/results/<date>/<step>/<method>/...`

### Metrics (minimum)

* Divergences, treedepth hits
* Runtime
* Basic posterior sanity checks
* For synthetic: recovery metrics (if available)

### Success criteria

* Ladder runner works end-to-end.
* Establish baseline results for v0.2.1 tag.
* Used as acceptance gate for A1/A2/A3.

## B1. Downsampled / Hierarchical HMM (Exploratory but Supported)

### Goal

Enable scalable temporal modeling for long recordings via a downsampled (low-rate) HMM used as a prior over full-rate movement.

### Scope

* Implement **Variant 1 (block-tied states)** first:

  * z defined at low rate, shared across m-frame blocks
* Optionally prototype **Variant 2 (regime + continuous deviation)**

### Implementation

* `gimbal/hmm/downsampled.py`

  * `collapsed_hmm_loglik_blocked(logp_emit, logp_init, logp_trans, block_size)`
  * utilities for mapping full-rate emissions to block-rate states

### Tests

* Synthetic tests verifying equivalence to full HMM under block-constant assumption
* Stability tests at long T

### Success criteria

* Demonstrate improved scaling with T while maintaining interpretability.

## E1. Hierarchical Priors with Sequential Updating (Important, later in cycle)

### Goal

Introduce a path toward population-level learning where hyperparameters can be updated as new subjects arrive.

### Scope

* Start with hierarchical priors on segment lengths and possibly kappa.
* Provide “fit population once” then “use as prior for new subject” workflow.
* Avoid overengineering; focus on a minimal working example.

### Deliverables

* `gimbal/priors/hierarchical.py`
* Demo notebook showing sequential updating concept

### Success criteria

* Clear workflow for reusing learned hyperpriors across subjects.
